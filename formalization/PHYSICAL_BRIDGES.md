# From a checked model to a physical theorem

A physical assertion in this archive names an actual parameter, iterate, domain, boundary access, curve family or marked tower. A proof about that object may be formal or written. A proof about an integer array, an abstract group or a list of predicates has a different subject. The tables identify the intervening map or lemma and the evidence for it. The [two-scale proof audit](TWO_SCALE_PHYSICAL_BRIDGES.md) and [tip-family proof audit](../research/tip_family_theorem/PHYSICAL_BRIDGES.md) give the individual steps for the two main dynamical applications.

**How to check a claim.** Start at its conclusion. Fix the parameter, period, domain, marking, orientation, boundary condition and quantifiers in that row. Follow the named inputs on those same objects. A **formal** row names a Lean result, a **written** row gives a mathematical argument, and an **imported** row identifies a published theorem and its domain of application. **Model** and **diagnostic** rows stop at their indicated objects. An **open** row states a lemma to prove. A **conditional** conclusion consumes its hypotheses even if its last algebraic step has been kernel-checked. The input column records other rows used on the indicated route. Hypotheses local to a single row appear in its proof column. Historical manuscripts and source locks retain their dates.

## Reproduction and coverage

The [source index](physical_bridge_sources.tsv) maps each archive Lean source, each research Python audit or generator, and the numerical experiments to the applicable rows. The November entries in [ledger.json](../ledger.json) cite the same IDs in `physical_bridges`. Several rows can apply to one file. A source pointer is a way to find a claim. It does not certify the contents of a paper or establish a geometric hypothesis.

Run `python3 code/verify_physical_bridges.py` from the repository root to check source coverage, dependency closure, status consistency and evidence paths. For the formal results run `lake build` in the root project and `lake exe cache get && lake build` in `formalization/weighted` with their pinned Lean toolchains. Reproduce each finite certificate using the command in its linked proof audit. To review a written or imported step, compare its hypotheses to the defined source objects before using its conclusion.
